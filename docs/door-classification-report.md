### 最小實作組合建議

從上表可以看出,113 個門型的動畫多樣性其實極低——絕大多數落在少數幾套骨架上。若要用最少工程覆蓋最多門型,優先順序:

1. **鉸鏈單開 + 鉸鏈雙開(+ 鏡頭穿越)** — 涵蓋所有 a/b 類一般門,是絕對主力(約佔可做門型的 6 成以上)。你們現有的 `DoorAnimation3D`(開門 → 鏡頭前進 → 淡出)就是這一套,單門版已完成。雙門版只是加一片鏡像門板。
2. **水平滑動 + 中分滑動** — 涵蓋所有拉門、自動門、電梯門(僅門體)。中分滑動 = 兩片對開的水平滑動,骨架共用。
3. **純鏡頭移動** — 涵蓋全部 c 類階梯/直梯/升降平台/鑽洞,不需門模型,只需場景幾何 + 鏡頭路徑。
4. **少數特例骨架**:雙門僅單扇開(參數化:開一扇 / 兩扇)、垂直上升/捲升、窄雙板折疊。各只服務 1–3 個門型,可視優先級決定是否做。

**配件**才是真正需要逐一準備的資產,但也可歸納成一組可重用元件:無把 / 喇叭鎖 / 豎把 / 橫把 / 彎把 / 斜把 / 圓環 / 門栓 / 轉盤鎖 / 自動(無配件)。這 10 種把手 + 上述約 4 套動畫骨架 + 逐門換的平面貼圖,即可組出全部可做門型。

**結論**:成本幾乎不在「動畫」(骨架就這幾套),而在**配件模型**與**逐門貼圖量**。原 CSV 的 130 小時裡,真正的變異來自後兩者,而非動畫本身。
